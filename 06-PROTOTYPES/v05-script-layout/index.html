M — MechanicsHow does it work?

The mechanical process, sequence, rules and implementation that allow a system to function.

M
FUNCTIONProcesses · roles · software · policies · workflows · escalation
E — ExperienceWhat does it feel like?

The human layer: perception, confidence, friction, cognition, emotion and memory.

E²
ADOPTIONExperience compounds usability, trust, clarity and repeat behaviour.
N — NecessityWhy must it exist? / PAUSED

The underlying reason a function deserves resources, attention and continued existence.

N
PURPOSEWhat problem disappears because this exists? What happens if it is removed?
Working modelEMC

System value ≈ M × E² × N

A functioning system with no meaningful experience struggles to gain adoption. A pleasant system with no necessity has little reason to survive.

Internal service testDecision layer

Before improving a function, establish whether the function deserves to remain.

KEEP
Necessary + functional + usable.
SIMPLIFY
Necessary, but burdened by mechanics.
AUTOMATE
Necessary, repetitive and rule-based.
OUTSOURCE
Necessary, but non-core to the system.
REMOVE
Low necessity, regardless of how well it works.
Design principleClosing statement

People use mechanics, remember experiences, and return because of necessity.
